# СТАЛЬТРАССА

Сайт металлических кабельных лотков: главная, каталог, страницы серий, доставка и оплата, контакты.

| Страница | Адрес |
| --- | --- |
| Главная | `/` |
| Каталог | `/catalog` |
| Перфорированный лоток | `/catalog/perforated` |
| Лестничный лоток | `/catalog/ladder` |
| Глухой лоток | `/catalog/solid` |
| Доставка и оплата | `/delivery` |
| Контакты | `/contacts` |
| Админка | `/admin` |

Нужен Node.js 22. Заявки с формы остаются в браузере. Чтобы правки текстов из админки не пропадали, нужна база Postgres — переменная `DATABASE_URL`.

## Локальный запуск

```bash
npm install
npm run dev
```

Сайт откроется на `http://127.0.0.1:8080`.

Проверка типов: `npm run typecheck`.

## Сборка

```bash
npm install
npm run build
npm run preview
```

`npm run build` собирает клиент и сервер в формате Vercel и пишет результат в `.vercel/output`. Отдельный каталог `dist` не используется.

Без `DATABASE_URL` миграции пропускаются. Для просмотра сайта это нормально: тексты остаются исходными.

`npm run preview` поднимает собранную версию на `http://127.0.0.1:8081`.

## Как менять текст

Тексты правятся в админке. Ссылка **Админка** стоит в подвале сайта.

1. Откройте её и войдите через Google или X.
2. Первый вошедший аккаунт становится администратором. Другие войти могут, но сохранить текст не смогут.
3. Меняйте заголовки, серии, отзывы, контакты и вступление к доставке, затем нажмите **Сохранить**. Текст сразу виден всем.

Фото, таблицы размеров и цены по-прежнему в коде.

На своём проекте Vercel задайте `DATABASE_URL` (Postgres) в **Settings → Environment Variables**. Без базы правки не сохранятся после перезапуска.

## Деплой на Vercel

Сайт собирается пресетом Nitro `vercel`. Команда `npm run build` сама готовит выход. Каталог сборки в настройках указывать не нужно.

### Первый проект

1. Войдите на [vercel.com](https://vercel.com) под аккаунтом с доступом к GitHub `Krapivin1986`.
2. **Add New → Project** и импортируйте [Krapivin1986/staltrassa](https://github.com/Krapivin1986/staltrassa). Если репозитория нет в списке, нажмите **Adjust GitHub App Permissions** и разрешите доступ.
3. На экране настройки оставьте:
   - **Framework Preset** — `Other`. Не выбирайте Next.js: это не Next-проект.
   - **Root Directory** — корень репозитория, `./`.
4. Раскройте **Build and Output Settings**.

   | Поле | Значение |
   | --- | --- |
   | Install Command | `npm install --omit=dev --no-audit --no-fund` |
   | Build Command | `npm run build` |
   | Output Directory | пусто |

   Install Command уже задан в `vercel.json`. Если поле пустое, Vercel возьмёт его оттуда. Output Directory оставьте пустым: `dist`, `public` или `.vercel/output` сломают деплой.
5. В **Environment Variables** добавьте `DATABASE_URL`, если нужна админка с сохранением текстов. Для простого показа сайта переменные не обязательны.
6. Нажмите **Deploy** и дождитесь статуса Ready.

### После создания проекта

В **Settings → General** выставьте **Node.js Version** `22.x`.

В **Settings → Git** производственная ветка должна быть `main`: пуш в неё запускает новый деплой сам.

Пока домен не подключён, сайт открывается на `*.vercel.app`. Проверьте адреса из таблицы в начале.

## Свой домен

Домен подключается в уже задеплоенном проекте. Vercel сам выпустит сертификат, как только DNS станет верным.

1. Откройте проект и перейдите в **Settings → Domains**.
2. Нажмите **Add Domain** и введите домен, например `staltrassa.ru`. Vercel предложит добавить и `www`. Соглашайтесь: так оба адреса будут открывать сайт.
3. На карточке домена Vercel покажет нужные записи. Скопируйте их в панель регистратора (Reg.ru, Timeweb, Cloudflare и т.п.). Не берите IP из чужой инструкции: у проекта он свой.

   | Адрес | Тип | Имя | Значение |
   | --- | --- | --- | --- |
   | `staltrassa.ru` | A | `@` | IP со страницы Domains, часто `76.76.21.21` или `216.198.79.1` |
   | `www.staltrassa.ru` | CNAME | `www` | цель, которую показывает Vercel, вида `xxxx.vercel-dns-017.com` |

4. Старые A и CNAME для `@` и `www` удалите. Записи почты (MX, TXT для SPF) не трогайте.
5. Если домен уже был у другого аккаунта Vercel, добавьте TXT-запись на `_vercel` с текстом, который покажет панель.
6. Подождите от нескольких минут до суток. Статус должен смениться на **Valid Configuration**. После этого HTTPS включается сам.
7. На том адресе, который не основной, включите **Redirect**, чтобы `www` вёл на домен без `www` или наоборот.

> Nameservers на `ns1.vercel-dns.com` и `ns2.vercel-dns.com` менять не нужно, если DNS и почта уже живут у регистратора. В Cloudflare на время проверки выключите прокси (серое облако): оранжевое прячет записи, и Vercel не видит их.
