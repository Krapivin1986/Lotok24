# Лоток24

Сайт металлических кабельных лотков: главная, каталог, страницы серий, доставка и оплата, блог, контакты.

| Страница | Адрес |
| --- | --- |
| Главная | `/` |
| Каталог | `/catalog` |
| Перфорированный лоток | `/catalog/perforated` |
| Лестничный лоток | `/catalog/ladder` |
| Глухой лоток | `/catalog/solid` |
| Доставка и оплата | `/delivery` |
| Блог | `/blog` |
| Контакты | `/contacts` |
| Админка | `/admin` |

Нужен Node.js 22. Заявки с формы остаются в браузере посетителя. Тексты из админки сохраняются только при заданном `DATABASE_URL`.

## Локальный запуск

```bash
npm install
npm run dev
```

Сайт откроется на `http://127.0.0.1:8080`.

Проверка типов: `npm run typecheck`.

## Сборка

```bash
npm install
npm run build
npm run preview
```

`npm run build` собирает клиент и сервер в формате Vercel и пишет результат в `.vercel/output`. Отдельный каталог `dist` не используется.

Без `DATABASE_URL` миграции пропускаются. Для просмотра сайта это нормально: тексты остаются исходными.

`npm run preview` поднимает собранную версию на `http://127.0.0.1:8081`.

## Как менять текст

Тексты правятся в админке. Ссылка **Админка** стоит в подвале сайта.

1. Откройте её и войдите через Google или X.
2. Первый вошедший аккаунт становится администратором. Другие войти могут, но сохранить текст не смогут.
3. Меняйте заголовки, серии, отзывы, контакты и вступление к доставке, затем нажмите **Сохранить**. Текст сразу виден всем.

Фото, таблицы размеров и цены по-прежнему в коде.

На своём проекте Vercel задайте `DATABASE_URL`, как в разделе [Деплой на Vercel](#деплой-на-vercel). Без базы правка не остаётся: на сервере она живёт только в памяти процесса и пропадает.

Вход через Google или X в предпросмотре работает сразу. На своём адресе `*.vercel.app` тех же кнопок недостаточно: брокер принимает их только вместе с клиентом, выданным для этого адреса (`GROK_AUTH_CLIENT_ID` и `GROK_AUTH_CLIENT_SECRET`). Без него сайт открывается, тексты остаются исходными.

## Деплой на Vercel

Сайт публикуется из GitHub. Сборка идёт пресетом Nitro `vercel`: `npm run build` сам пишет `.vercel/output`. Каталог `dist` указывать не нужно.

### 1. Импорт

1. Войдите на [vercel.com](https://vercel.com) под аккаунтом с доступом к GitHub `Krapivin1986`.
2. **Add New → Project**.
3. Выберите [Krapivin1986/staltrassa](https://github.com/Krapivin1986/staltrassa). Если репозитория нет в списке, нажмите **Adjust GitHub App Permissions** и разрешите к нему доступ.

### 2. Сборка

На экране настройки:

| Поле | Значение |
| --- | --- |
| Framework Preset | `Other`. Не Next.js |
| Root Directory | `./` |
| Install Command | `npm install --omit=dev --no-audit --no-fund` |
| Build Command | `npm run build` |
| Output Directory | пусто |

Install Command уже записан в `vercel.json`. Если поле пустое, Vercel возьмёт его оттуда.

> Output Directory оставьте пустым. `dist`, `public` или `.vercel/output` сломают деплой: Vercel сам читает `.vercel/output`.

### 3. Переменные

Для показа сайта переменные не нужны. Чтобы админка сохраняла тексты, нужна база и стабильный секрет сессии.

| Имя | Зачем | Что подставить |
| --- | --- | --- |
| `DATABASE_URL` | Postgres для текстов и учёток | строка подключения. Приложению нужно именно это имя |
| `BETTER_AUTH_SECRET` | подпись сессии, одна на все экземпляры | случайная строка от 32 символов |
| `BETTER_AUTH_URL` | адрес, с которого открывают сайт | `https://<проект>.vercel.app`, без `/` в конце |
| `GROK_AUTH_CLIENT_ID` | клиент входа Google и X | выдаётся для этого адреса, не из чужого проекта |
| `GROK_AUTH_CLIENT_SECRET` | секрет того же клиента | пара к `GROK_AUTH_CLIENT_ID` |

Базу подключают так:

1. Откройте [Vercel Marketplace](https://vercel.com/marketplace) и установите Neon (или другой Postgres) в этот проект. Пункт **Storage → Create Database** больше не создаёт Postgres: своя база Vercel закрыта, новые проекты берут её из Marketplace.
2. Если интеграция записала строку под другим именем, например `POSTGRES_URL`, скопируйте значение в `DATABASE_URL`.
3. Оставьте переменную доступной и при сборке, и в рантайме. Миграции запускаются внутри `npm run build`. Если на сборке строки нет, таблицы не создадутся.

`BETTER_AUTH_URL` без слэша на конце. После своего домена замените значение на `https://ваш-домен.ru` и задеплойте ещё раз. Секреты в репозиторий не кладите.

Без `GROK_AUTH_CLIENT_ID` и `GROK_AUTH_CLIENT_SECRET` кнопки Google и X на `*.vercel.app` не завершат вход: запасной клиент брокера принимает только адреса предпросмотра. Сайт при этом публикуется и показывает исходные тексты.

### 4. Node.js

До нажатия **Deploy** поставьте **Node.js Version** `22.x`: на экране импорта, если поле есть, иначе в **Settings → General** сразу после создания проекта и до повторной сборки.

В **Settings → Git** производственная ветка — `main`.

### 5. Публикация

Нажмите **Deploy** и дождитесь статуса **Ready**. Пока домен не подключён, сайт открывается на `*.vercel.app`.

Проверьте:

| Страница | Адрес |
| --- | --- |
| Главная | `/` |
| Каталог | `/catalog` |
| Серии | `/catalog/perforated`, `/catalog/ladder`, `/catalog/solid` |
| Доставка | `/delivery` |
| Контакты | `/contacts` |
| Админка | `/admin` |

### Повторный деплой

Пуш в `main` запускает сборку сам. Вручную: **Deployments → … → Redeploy**.

Если сборка красная, сначала проверьте три вещи: Framework Preset не Next.js, Output Directory пустой, Node.js `22.x`.

## Свой домен

Домен подключается в уже задеплоенном проекте. Vercel сам выпустит сертификат, как только DNS станет верным.

1. Откройте проект и перейдите в **Settings → Domains**.
2. Нажмите **Add Domain** и введите домен, например `lotok24.ru`. Vercel предложит добавить и `www`. Соглашайтесь: так оба адреса будут открывать сайт.
3. На карточке домена Vercel покажет нужные записи. Скопируйте их в панель регистратора (Reg.ru, Timeweb, Cloudflare и т.п.). Не берите IP из чужой инструкции: у проекта он свой.

   | Адрес | Тип | Имя | Значение |
   | --- | --- | --- | --- |
   | `lotok24.ru` | A | `@` | IP со страницы Domains, часто `76.76.21.21` или `216.198.79.1` |
   | `www.lotok24.ru` | CNAME | `www` | цель, которую показывает Vercel, вида `xxxx.vercel-dns-017.com` |

4. Старые A и CNAME для `@` и `www` удалите. Записи почты (MX, TXT для SPF) не трогайте.
5. Если домен уже был у другого аккаунта Vercel, добавьте TXT-запись на `_vercel` с текстом, который покажет панель.
6. Подождите от нескольких минут до суток. Статус должен смениться на **Valid Configuration**. После этого HTTPS включается сам.
7. На том адресе, который не основной, включите **Redirect**, чтобы `www` вёл на домен без `www` или наоборот.

> Nameservers на `ns1.vercel-dns.com` и `ns2.vercel-dns.com` менять не нужно, если DNS и почта уже живут у регистратора. В Cloudflare на время проверки выключите прокси (серое облако): оранжевое прячет записи, и Vercel не видит их.
